# PRD — 베뉴픽 (VenuePick)

---

## 1. 프로젝트 개요

| 항목 | 내용 |
|---|---|
| 이름 | 베뉴픽 (VenuePick) |
| 한 줄 설명 | 이해관계 없는 실사용자 인증 리뷰로, MICE 시설·벤더 선정의 정보 비대칭을 해소하는 B2B 비교 플랫폼 |
| 유형 | B2B 정보/리뷰 플랫폼 (Review & Comparison SaaS) |
| 난이도 | 중 (2주 완성 기준) |

---

## 2. 사용자 시나리오

**누가**
행사를 기획·주관·대행하는 마이스 업계 실무자 — PCO 대행사 담당자, 기업 사내 이벤트 담당자, 프리랜서 이벤트 기획자 등 시설·벤더를 선정하거나 실제로 이용해본 경험이 있는 사람.

**언제**
- 새로운 행사를 수주·기획하면서 시설·벤더 후보를 처음 탐색할 때, 특히 기존 거래처가 아닌 신규 옵션을 검토해야 할 때
- 행사가 끝난 직후, 자신의 이용 경험을 기록해서 다음 담당자나 동료가 참고할 수 있게 남기고 싶을 때

**왜**
스펙시트나 지인 네트워크만으로는 알 수 없는 실사용 정보(네트워크 안정성, 소음, 하역 접근성, 실제 예산대)를 사전에 파악해 리스크 없는 선택을 하기 위해, 그리고 인맥이 부족한 사람도 이해관계 없는 제3자 리뷰를 통해 정보 격차 없이 판단할 수 있게 하기 위해.

## 3. 핵심 기능 목록

### 필수 기능 (MVP)

| 기능 | 설명 |
|---|---|
| 시설/벤더 리스트 & 검색·필터 | 지역, 유형(컨벤션홀/전시장/케이터링 등), 수용인원, 평점순 필터링 |
| 리뷰 작성/조회 | 로그인 후 카테고리별 세부 평점(가격/접근성/시설/서비스) + 텍스트 리뷰 작성 |
| 인증 리뷰 뱃지 | 영수증/계약서 첨부 시 "✓ 인증 후기" 표시 (익명 유지) |
| Google 소셜 로그인 | 리뷰 작성은 로그인 사용자만 가능 |
| AI 리뷰 요약 | Gemini API로 리뷰 텍스트에서 장단점 자동 요약 + 키워드 추출 |
| 비교 대시보드 | 시설별 만족도 도넛차트, 리뷰 워드클라우드, 항목별 통계 카드 |
| 반응형 랜딩페이지 | 데스크탑/모바일 대응 메인 페이지 |
| 배포 & SEO | Vercel 배포, 메타태그/OG 이미지 설정 |

### 선택 기능

없음 (전량 MVP로 통합)

## 4. 기술 스택

| 영역 | 선택 | 이유 |
|---|---|---|
| 프론트엔드 | Next.js (App Router) | 커리큘럼 기본 스택, 랜딩페이지·SEO 대응 용이 |
| 스타일링 | Tailwind CSS | 반응형 작업 속도, 커리큘럼 반영 |
| 백엔드/DB | Supabase (PostgreSQL) | 인증+DB+스토리지 통합, 별도 백엔드 구현 불필요 |
| 인증 | Supabase Auth (Google OAuth) | 별도 로그인 서버 구현 불필요 |
| 파일 저장 | Supabase Storage | 인증 리뷰용 영수증/계약서 첨부 파일 저장 (비공개 버킷) |
| AI 분석 | Google AI Studio (Gemini API) | 리뷰 감성분석, 키워드 추출, 장단점 요약 |
| 데이터 시각화 | Recharts (도넛차트) + 워드클라우드 라이브러리 | 대시보드 구현 |
| 배포 | Vercel | Next.js와 자연스러운 연동 |
| 버전관리 | Git + GitHub | 커밋 히스토리가 포트폴리오 증빙 자료 역할 |

**참고**
- 인증 리뷰 첨부파일은 Supabase RLS(Row Level Security)로 비공개 접근 제어
- 워드클라우드 라이브러리 불안정 시 D3.js로 직접 구현 대안 고려

## 5. 화면 구성

### 페이지 (Route) — 3개

| 페이지 | 통합된 요소 |
|---|---|
| ① 홈 | 랜딩(히어로+추천시설) + 시설 리스트(검색·필터·결과 그리드) 통합 |
| ② 시설 상세 | 기본정보, AI 요약(장단점 자동 요약), 항목별 평점 대시보드(도넛차트+통계카드), 리뷰 워드클라우드, 리뷰 리스트(인증뱃지 표시) |
| ③ 마이페이지 | 내가 쓴 리뷰 목록, 수정/삭제 (CRUD 시연용) |

### 모달/리다이렉트 (별도 페이지 아님)

| 기능 | 방식 |
|---|---|
| 로그인 | 헤더의 로그인 버튼 클릭 시 Google OAuth로 바로 이동(리다이렉트) → 인증 후 원래 페이지로 복귀. 리뷰 작성 버튼을 미로그인 상태로 눌러도 동일하게 로그인으로 이동, 복귀 후엔 버튼을 한 번 더 눌러 작성 이어감 |
| 리뷰 작성 | 시설 상세 페이지 안에서 모달/슬라이드패널로 작성. 카테고리별 평점 + 텍스트 + 영수증·계약서 첨부(선택) + 인증뱃지 부여 |

### 흐름 (User Flow)

```
[홈: 랜딩+리스트 통합] ──클릭──▶ [시설 상세]
                                      │
                              (리뷰 작성 버튼)
                                      │
                    로그인 안 됨? → Google OAuth로 이동 → 복귀
                                      │
                          (사용자가 리뷰 작성 버튼 다시 클릭)
                                      │
                              [리뷰 작성 모달/패널]
                                      │
                              같은 페이지에서 즉시 반영

헤더 상시 노출: [로그인/로그아웃] · [마이페이지] 링크
```

## 6. 상세 기능 명세

### 6-1. 시설/벤더 리스트 & 검색·필터
*(화면: 홈)*

| 항목 | 내용 |
|---|---|
| 트리거 | 홈 진입 시 기본 리스트 노출, 검색어/필터 입력 시 결과 갱신 |
| 입력 | 검색어(텍스트), 필터(지역/유형/수용인원 범위/평점순 정렬) |
| 처리 | Supabase 쿼리로 필터 조건 WHERE절 구성 → 정렬 옵션 적용(평점순/최신순) |
| 출력 | 시설 카드 그리드 (썸네일, 이름, 지역, 평균평점, 리뷰 수, 대표 키워드 태그) |
| 예외처리 | 검색 결과 0건 시 "조건에 맞는 시설이 없어요" 빈 상태 화면 + 필터 초기화 버튼 |

### 6-2. 리뷰 작성/조회
*(화면: 시설 상세 → 모달)*

| 항목 | 내용 |
|---|---|
| 트리거 | 시설 상세 페이지 내 "리뷰 작성" 버튼 클릭 |
| 입력 | 카테고리별 별점(가격/접근성/시설/서비스, 각 1~5점), 텍스트 리뷰(최소 20자), 이용 시기, 영수증·계약서 첨부(선택) |
| 처리 | 로그인 여부 확인 → 미로그인 시 로그인 페이지로 리다이렉트 → 제출 시 Supabase에 저장, 첨부파일 있으면 Storage에 업로드 |
| 출력 | 제출 성공 토스트 + 시설 상세 페이지 리뷰 리스트에 즉시 반영 |
| 예외처리 | 텍스트 20자 미만 시 제출 버튼 비활성화, 첨부파일 5MB 초과 시 에러 메시지 |

### 6-3. 인증 리뷰 뱃지 *(간소화)*
*(화면: 시설 상세, 리뷰 작성 모달)*

| 항목 | 내용 |
|---|---|
| 트리거 | 리뷰 작성 시 영수증/계약서 첨부 여부 |
| 입력 | 첨부파일 (이미지 또는 PDF) |
| 처리 | 첨부 존재 시 `is_verified = true` 필드 저장. 자동 OCR 검증·관리자 검수는 스코프 밖 — "첨부됨=인증"으로 단순 처리 |
| 출력 | 리뷰 카드에 "✓ 인증된 이용 후기" 뱃지 노출. 작성자 익명 유지 |
| 예외처리 | 첨부 없이 제출 시 일반 리뷰로 처리, 뱃지 없음. 버킷 권한 이슈 발생 시 공개 버킷으로 대체 가능 |

### 6-4. Google 소셜 로그인 *(간소화)*
*(화면: 별도 로그인 리다이렉트)*

| 항목 | 내용 |
|---|---|
| 트리거 | 헤더의 로그인 버튼, 또는 리뷰 작성 시도 시 미로그인 상태 |
| 처리 | Supabase Auth의 Google OAuth 리다이렉트 플로우 호출 → 인증 성공 시 세션 저장 후 원래 페이지로 복귀 |
| 출력 | 로그인 성공 후 같은 화면으로 복귀. 리뷰 작성은 사용자가 버튼을 다시 눌러 이어감 (자동 재개 없음) |
| 예외처리 | OAuth 실패/취소 시 로그인 전 화면으로 복귀, 별도 에러 처리 없이 조용히 무시 |

### 6-5. AI 리뷰 요약 *(간소화)*
*(화면: 시설 상세)*

| 항목 | 내용 |
|---|---|
| 트리거 | 시설 상세 페이지 로드 시, 해당 시설 리뷰 5개 이상 존재할 때 |
| 입력 | 해당 시설의 전체 리뷰 텍스트 |
| 처리 | Gemini API 호출 → "장점 3가지, 단점 3가지, 키워드 5개"를 JSON으로 요청 → 파싱 후 화면에 바로 렌더링 (캐싱 없이 페이지 로드마다 재호출) |
| 출력 | 상세페이지 상단 "AI 요약" 카드로 장단점 리스트 + 키워드 태그 노출 |
| 예외처리 | 리뷰 5개 미만 시 "리뷰가 더 쌓이면 AI 요약을 제공해요" 안내, API 실패 시 "요약을 불러오지 못했어요" 메시지 |

### 6-6. 비교 대시보드
*(화면: 시설 상세)*

| 항목 | 내용 |
|---|---|
| 트리거 | 시설 상세 페이지 로드 시 |
| 입력 | 해당 시설의 카테고리별 평점 데이터, 리뷰 텍스트(키워드용) |
| 처리 | 카테고리별 평균 계산 → 도넛차트용 데이터 가공, 키워드 빈도 집계 → 워드클라우드용 데이터 가공 |
| 출력 | 도넛차트(항목별 만족도), 통계 카드(평균 평점, 리뷰 수, 인증 리뷰 비율), 워드클라우드 |
| 예외처리 | 리뷰 0건 시 "아직 등록된 리뷰가 없어요" 빈 상태 처리 |

### 6-7. 반응형 랜딩페이지
*(화면: 홈 상단)*

| 항목 | 내용 |
|---|---|
| 구성 | 히어로(핵심 카피+검색창), 추천/인기 시설 섹션, 서비스 소개 섹션 |
| 처리 | Tailwind 반응형 브레이크포인트로 모바일/데스크탑 레이아웃 전환 |
| 예외처리 | 없음 (정적 콘텐츠 위주) |

### 6-8. 배포 & SEO
*(전역)*

| 항목 | 내용 |
|---|---|
| 처리 | Vercel 배포, 환경변수(Supabase/Gemini API 키) 설정, 메타태그(title/description) 및 OG 이미지 설정 |
| 출력 | 배포된 URL, 카카오톡/슬랙 등에 링크 공유 시 미리보기 카드 정상 노출 |
| 예외처리 | 환경변수 미설정 시 빌드 실패 방지를 위해 `.env.example` 파일 별도 관리 |

## 7. 디자인 가이드

### 무드 & 톤
글래스모피즘(Glassmorphism) 기반의 다크·라이트 하이브리드 UI.
반투명 카드가 배경 위에 부유하는 듯한 레이어감, 부드러운 그림자(Soft UI)로
전문적이면서도 미래지향적인 신뢰감을 전달한다. B2B 데이터 서비스에 맞게
"딱딱한 관공서 톤"이 아니라 "정제된 대시보드 톤"을 지향한다.

### 컬러 팔레트

| 용도 | 컬러 | HEX |
|---|---|---|
| Primary (액션/포인트) | 일렉트릭 블루 | #3E6BFF |
| Deep Background (다크 섹션) | 딥 네이비 | #0B1526 |
| Base Background (라이트 섹션) | 소프트 그레이 화이트 | #F4F6FA |
| Surface / Glass Card | 화이트 글래스 | rgba(255,255,255,0.55) + blur |
| Surface / Glass Card (다크용) | 네이비 글래스 | rgba(20,35,60,0.55) + blur |
| Text Primary | 잉크 네이비 | #10192B |
| Text Secondary | 그레이 블루 | #6B7A99 |
| Accent (인증/긍정) | 스카이 블루 그라데이션 | #4F8CFF → #8AB4FF |

- 전체적으로 유채색은 블루 계열 한 가지로 통일하고, 채도·명도 변화로 위계를 표현한다.
- 경고/부정적 정보(예: 이슈 리포트)에만 예외적으로 warm 톤(앰버 계열, #E8A33D) 소량 사용.

### 타이포그래피
- 헤드라인: 굵고 간결한 Sans-serif (예: Pretendard Bold / Space Grotesk)
- 본문: 가독성 높은 Sans-serif (예: Pretendard Regular / Inter)
- 숫자·통계 데이터: 고정폭 느낌의 모노스페이스 보조 사용 (예: JetBrains Mono) — 평점, 가격대 등 데이터성 정보에 적용해 "정확한 정보"라는 인상 강화

### 컴포넌트 스타일
- **카드**: 큰 라운드 코너(16~24px), 반투명 배경 + 블러(backdrop-filter) 처리, 얇은 흰색 테두리(1px, opacity 낮게)로 유리질감 표현
- **버튼**: Pill 형태(완전 둥근 모서리), Primary 버튼은 블루 단색 또는 블루 그라데이션 채움
- **아이콘**: 라인 아이콘 기반, 원형/둥근 사각 배경 칩(chip) 안에 배치
- **그림자**: 진하고 딱딱한 그림자 대신, 낮은 불투명도의 넓게 퍼지는 소프트 섀도우 사용

### 데이터 시각화 스타일
- 도넛차트·그래프에는 카드와 통일된 블루 그라데이션 적용 (예: 라인 아래 영역을 블루→투명 그라데이션으로 채움)
- 통계 카드는 큰 숫자 + 작은 라벨 구조, 카드 자체도 글래스 스타일 유지
- 워드클라우드는 블루 계열 명도 차이로 빈도 표현 (강조 단어일수록 진한 블루)

### 인터랙션 / 모션
- 카드 진입 시 부드러운 페이드+슬라이드업 (과하지 않게, 150~250ms)
- 호버/탭 시 카드가 살짝 떠오르는 느낌(그림자 확장 + 미세한 scale-up)
- 로딩 상태는 스켈레톤(glass 카드 형태 그대로 회색 펄스)으로 처리해 톤 일관성 유지

### 라이트/다크 적용 기준
- 홈·리스트: 라이트 베이스 (화이트/소프트그레이 배경, 블루 포인트)
- 시설 상세의 AI 요약·대시보드 섹션: 다크 네이비 배경 + 글래스 카드로 "데이터 인사이트" 영역임을 시각적으로 구분

## 8. 제약사항

### 스코프 밖 (Out of Scope)
- 인증 리뷰 자동 검증(OCR/AI 판독) — 첨부 파일 존재 여부만으로 "인증"으로 간이 처리
- 관리자 검수/신고 처리 워크플로우
- 리뷰 신고·삭제 요청 프로세스
- AI 요약 결과 캐싱 — 페이지 로드마다 재호출
- 2~3개 시설 비교 테이블 화면
- 결제/유료화 기능
- 다국어 지원 (한국어만 제공)

### 기술적 제약
- Gemini API 무료 티어 사용 시 요청 속도 제한(rate limit) 존재 가능 — 트래픽 몰릴 경우 요약 지연/실패 가능
- Supabase 무료 플랜 기준 DB·Storage 용량 제한 — 첨부파일 누적 시 용량 초과 우려
- 첨부파일 내 개인정보(회사명, 담당자명, 금액 등) 마스킹 처리는 자동화하지 않고 최소 수준(비공개 버킷 처리)에 그침
- 워드클라우드·차트 라이브러리는 React 생태계 내 안정성이 낮은 경우가 있어, 필요 시 대체 구현(D3.js 등)으로 전환될 수 있음

### 법적/윤리적 고려사항
- 익명 리뷰의 명예훼손·허위사실 게재 리스크에 대한 대응 정책이 MVP 단계에서는 마련되어 있지 않음 (실 서비스화 시 신고·중재 프로세스 필요)
- 첨부파일(영수증·계약서)에 포함될 수 있는 제3자 개인정보·기업정보에 대한 명확한 처리 방침이 미비함 — 현재는 비공개 저장으로 최소한의 보호만 적용
- 리뷰 작성자의 익명성과 인증 정보(첨부파일) 간 연결 관계가 데이터베이스 내부적으로는 존재하므로, 완전한 익명성이 기술적으로 보장되는 것은 아님을 사용자에게 고지할 필요
